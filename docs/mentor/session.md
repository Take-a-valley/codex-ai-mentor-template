# 開始・再開・ログ管理・終了

## 適用

開始、再開、引き継ぎ、ログ更新、終了報告に使用する。共通ルールは[AGENTS.md](../../AGENTS.md)、手順の選択は[PROMPT.md](../../PROMPT.md)を参照する。

## 開始・再開

1. current_tasks.mdの「初回検証・記録への利用者承認」を確認する。「未確認」の場合は、初期検証を実施し、検証結果と必要な変更履歴を記録してよいか利用者に尋ねる。回答がなければ検証・記録をせず、通常の作業は続けてよい。
2. 承認されたら状態を「承認済み」としてcurrent_tasks.mdに記録し、[validation.md](validation.md)の初回確認を検証用コピーで実施する。結果を記録し、検証によってテンプレート自体に反映した変更がある場合はCHANGELOG.mdにも記録する。完了後は状態を「完了」にする。
3. 承認されなかった場合は状態を「拒否」としてcurrent_tasks.mdに記録し、検証・検証結果の記録・変更履歴の更新を行わない。後の起動で再度確認しない。明示的に改めて依頼された場合は、その依頼の範囲を確認してから対応する。
4. 「承認済み」「完了」「拒否」の場合は、初回確認を繰り返さない。承認は初回検証とその結果記録に限り、他の編集・Git操作の許可を含まない。
5. docs/context/current_tasks.md、project_overview.md、architecture_summary.md、technology_stack.md、scope.md、decisions.md、open_questions.md、mentor_preferences.mdを確認する。未設定項目を事実として補完しない。
6. 最新のAI_mentor_log.mdを読み、必要ならAgenda_log.mdの関連箇所を確認する。履歴全件を毎回読む必要はない。
7. 対象タスクの設計書と実ファイルを照合する。存在、内容、作成済み、レビュー済み、コンパイル済み、テスト済みを区別する。
8. Git利用時は現在ブランチ・作業ツリー・関連コミットを読み取り確認する。リモート参照との一致を実際のリモート最新状態と混同しない。
9. 現状、残課題、次の具体的作業、未確認事項を簡潔に示す。初回承認状態の記録以外は、開始だけを理由に終了処理やファイル編集を行わない。

## 記録先と更新方法

- current_tasks.md：最新状態のみ。次回の再開位置、未検証事項、根拠を更新する。
- decisions.md：ユーザーの明示決定と既存資料で確認した決定のみ。提案は混ぜない。
- open_questions.md：不足、選択肢、影響、回答状況を記録する。
- learning_notes.md・glossary.md：学習事項と用語を必要に応じて記録する。
- AI_mentor_log.md：通常の作業、学習、レビュー、検証、残課題の履歴。
- Agenda_log.md：クライアントモードの議事録。

最新状態は整理・置換し、過去履歴はログに残す。ログは日付付きで追記し、後の変更で過去の実施事実を書き換えない。誤記は訂正と分かるよう修正する。
日付は利用者のタイムゾーンに従い、不明なら確認する。秘密情報と記録除外の指示を守る。
テンプレートの初回検証と検証記録・変更履歴の更新には、開始時に得た利用者の明示的な承認が必要です。通常の作業ログやタスク状態の更新には本項の初回承認を流用せず、各記録のルールと依頼範囲に従います。

## 終了報告

当日の実施内容・学習・判断・未解決事項・検証状況を整理し、AI_mentor_log.mdへ保存する。current_tasks.mdを最新の再開位置に更新する。必要な決定・未決事項も整合させる。
未実施や失敗を成功へ変換しない。保存に失敗したら対象と未保存内容を報告する。
終了報告だけでAgenda_log.mdを書き換えたり、クライアントモードを終了したりしない。クライアント終了は[client](client.md)に従う。
コミット・push・マージは終了報告から自動実行しない。
