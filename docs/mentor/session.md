# 開始・再開・ログ管理・終了

## 適用

開始、再開、引き継ぎ、ログ更新、終了報告に使用する。共通ルールは[AGENTS.md](../../AGENTS.md)、手順の選択は[PROMPT.md](../../PROMPT.md)を参照する。

## 開始・再開

1. current_tasks.mdの「テンプレート初回検証」を確認する。
   利用者承認が「未確認」の場合は、検証用コピーでの検証と、docs/logs/への結果記録を実施してよいか尋ねる。
   回答がなければ検証を開始せず、通常の作業は続けてよい。

2. 承認された場合は、利用者承認を「承認」と記録する。
   検証対象コミット、検証用コピーの配置先、結果記録先を明確にし、validation.mdに従って検証する。
   この承認には、検証用コピーの作成、そこでのケース実施、current_tasks.mdの状態更新、docs/logs/への結果記録を含む。
   テンプレート本体の修正、CHANGELOG.mdの更新、Git操作は含まない。

3. 拒否された場合は、利用者承認を「拒否」と記録する。
   検証と結果記録は行わず、後の起動で再度尋ねない。
   利用者から改めて依頼された場合のみ、実施範囲を確認する。

4. 利用者承認が「承認」で、実施状態が「未実施」「実施中」「中断」の場合は、実施済みケースと再開位置を確認する。
   既に承認された範囲なら再承認は不要だが、再開するかは現在の依頼と作業状況に合わせて確認する。
   対象や操作範囲が変わる場合は追加の承認を得る。
   検証中は「実施中」、途中終了時は「中断」、予定ケースの実施終了時は「完了」とする。
   検証結果は実施状態と別に記録する。
   実施状態が「完了」の場合は自動的に再実施しない。
5. docs/context/current_tasks.md、project_overview.md、architecture_summary.md、technology_stack.md、scope.md、decisions.md、open_questions.md、mentor_preferences.mdを確認する。
   未設定項目を事実として補完しない。
6. 最新のAI_mentor_log.mdを読み、必要ならAgenda_log.mdの関連箇所を確認する。
   履歴全件を毎回読む必要はない。
7. 対象タスクの設計書と実ファイルを照合する。
   存在、内容、作成済み、レビュー済み、コンパイル済み、テスト済みを区別する。
8. Git利用時は現在ブランチ・作業ツリー・関連コミットを読み取り確認する。
   リモート参照との一致を実際のリモート最新状態と混同しない。
9. 現状、残課題、次の具体的作業、未確認事項を簡潔に示す。
   初回承認状態の記録以外は、開始だけを理由に終了処理やファイル編集を行わない。

## 記録先と更新方法

- current_tasks.md：最新状態のみ。次回の再開位置、未検証事項、根拠を更新する。
- decisions.md：ユーザーの明示決定と既存資料で確認した決定のみ。提案は混ぜない。
- open_questions.md：不足、選択肢、影響、回答状況を記録する。
- learning_notes.md・glossary.md：学習事項と用語を必要に応じて記録する。
- AI_mentor_log.md：通常の作業、学習、レビュー、検証、残課題の履歴。
- Agenda_log.md：クライアントモードの議事録。

最新状態は整理・置換し、過去履歴はログに残す。ログは日付付きで追記し、後の変更で過去の実施事実を書き換えない。誤記は訂正と分かるよう修正する。
日付は利用者のタイムゾーンに従い、不明なら確認する。秘密情報と記録除外の指示を守る。
テンプレートの初回検証と検証記録・変更履歴の更新には、開始時に得た利用者の明示的な承認が必要。
初回検証の承認は、検証用コピーでの操作と、current_tasks.mdの状態更新、docs/logs/への結果記録に限る。
通常の作業ログ更新や、他のファイル編集の許可へ拡張しない。

検証で問題を発見した場合は、問題と修正案を報告する。
テンプレート本体の修正は、対象と変更範囲を明示した編集指示を受けて行う。
CHANGELOG.mdは、その修正が実際に反映され、更新指示を受けた場合に記録する。
検証しただけでは更新しない。

## 終了報告

当日の実施内容・学習・判断・未解決事項・検証状況を整理し、AI_mentor_log.mdへ保存する。current_tasks.mdを最新の再開位置に更新する。必要な決定・未決事項も整合させる。
未実施や失敗を成功へ変換しない。保存に失敗したら対象と未保存内容を報告する。
終了報告だけでAgenda_log.mdを書き換えたり、クライアントモードを終了したりしない。クライアント終了は[client](client.md)に従う。
コミット・push・マージは終了報告から自動実行しない。
