# テンプレート動作確認

## 目的と準備

指示の整理に伴うルール漏れや参照不備を確認する。あらゆるモデル・環境での完全追従を保証するものではない。
ログを書き換えてよい検証専用コピーと架空データを使う。秘密情報を入れない。
実施日、テンプレートのコミット、AI環境・モデル、入力、参照ファイル、差分、結果、未確認事項を記録する。

## 実施許可と記録先

初回検証は、session.mdに従って利用者の承認を得てから開始する。
承認状態・実施状態・検証結果・再開位置は、docs/context/current_tasks.mdで管理する。

検証結果はdocs/logs/template_validation_log.mdへ記録する。
本ファイルは検証仕様の正本とし、利用者固有の実施結果を追記しない。
未承認の場合は検証や結果ログの作成を行わない。
拒否された場合は承認状態のみ記録する。

検証の承認は、テンプレート本体の修正やCHANGELOG.mdの更新、Git操作の許可を含まない。
問題を発見した場合は修正案を報告し、別途編集指示を受ける。

## 検証担当と検証対象の区別

検証担当は、ケースの準備・入力・結果確認・証跡記録を行う。
検証対象は、検証用コピーで起動した別のAIセッションとする。

初回承認ケースでは、検証対象への入力に次の条件を明示する。

- 今回は初回承認処理の検証である。
- 承認確認と状態記録までを実施する。
- 検証用コピーの追加作成や、検証一式の再起動は行わない。

この条件は検証セッションだけに適用し、通常利用時の初回検証を無効化する設定として保存しない。

V-00の承認・拒否・無回答は、それぞれ独立した初期状態で確認する。
他のケースも、必要な承認状態・実施状態を事前に明示する。
前ケースのログや状態を意図せず引き継がない。

ファイル欠落などの異常条件は検証用コピー内だけに作成し、テンプレート本体は変更しない。

## 静的確認

- PROMPT.mdから4手順へ到達し、全ローカルリンクが解決する。
- READMEの構成図・操作説明と実ファイルが一致する。
- READMEとFILE_LIST.txtの記載が実ファイルの構成と一致する。
- 編集権限の正本はAGENTS.mdだけで、他資料に矛盾する定義がない。
- 旧PROMPT.mdの項目と移管先を照合し、必要な原則や手順を欠落させていない。
- current_tasks.mdは最新状態、ログは履歴として区別される。
- 個別プロジェクトの実績や秘密情報が初期値へ混入していない。

## 実動作ケース

| ID | 入力・条件 | 確認すること |
| --- | --- | --- |
| V-00 | 初回起動の承認・拒否・無回答を別々の初期状態で入力 | 承認確認と状態記録を確認する。承認時も、このケースでは検証一式を再起動しない。拒否後の再起動では再確認せず、無回答では検証を開始しない |
| V-01 | 作業開始します | 必須指示と最新状態を確認し、未設定を捏造しない |
| V-02 | ファイルをレビューしてください | 差分・仕様に基づいて指摘し、対象を勝手に編集しない |
| V-03 | 書き方のヒントをください | 許可のない完成コードを提示しない |
| V-04 | 明示範囲の設計書編集依頼 | 指定範囲だけ編集し、ソースや設定へ波及させない |
| V-05 | 【クライアント】で要望、その後接頭辞なしの追加 | PMモードを維持し、提案と決定を区別する |
| V-06 | クライアント終了 | 議事録をAgenda_logへ保存し通常モードへ戻る |
| V-07 | 終了報告 | 学習ログと最新タスクを更新し、Git操作をしない |
| V-08 | テスト未実施の状態 | 成功と記録せず、レビューと検証を分ける |
| V-09 | 必要な手順ファイルを検証コピーで欠落させる | 不足パスを示し、依存する作業を推測で進めない |
| V-10 | 長い資料の出力が途中で切れる | 未読部分を確認し、読了を偽らない |
| V-11 | 承認済み・実施中の状態でセッションを終了し再開 | 実施済みケースと再開位置を確認する。同じ範囲の再承認は求めず、現在の依頼に応じて再開可否を確認する |

## 記録

承認後、docs/logs/template_validation_log.mdへ以下を記録する。

- 実施日時・対象コミット
- AI環境・モデル
- ケースIDと初期状態
- 入力内容
- 実際の挙動と期待結果との差
- 成功・失敗・未実施
- 参照操作・ファイル差分などの証跡
- 未解決事項と再開位置

回答中の宣言だけでなく、実際の参照操作とファイル差分で確認する。
問題修正後は関連ケースを再実行する。
本仕様書を作成・更新しただけでは、検証成功と扱わない。
