# テンプレート動作確認

## 目的と準備

指示の整理に伴うルール漏れや参照不備を確認する。あらゆるモデル・環境での完全追従を保証するものではない。
ログを書き換えてよい検証専用コピーと架空データを使う。秘密情報を入れない。
実施日、テンプレートのコミット、AI環境・モデル、入力、参照ファイル、差分、結果、未確認事項を記録する。

テンプレートの初回起動時は、検証と検証結果・必要な変更履歴の記録を始める前に、利用者へ実施許可を確認する。確認状態はdocs/context/current_tasks.mdで管理し、承認後のみ検証用コピーを作成してケースを実施・記録する。回答がない場合は状態を未確認のままとし、検証・記録は行わない。拒否された場合は状態を記録し、以後の起動では再確認しない。初回承認を他のファイル編集やGit操作へ拡張しない。
CHANGELOG.mdはテンプレート自体に反映した変更がある場合のみ更新し、利用者固有の環境情報や検証結果の詳細はvalidation.mdへ記録する。初回検証を行わない場合、CHANGELOG.mdと本ファイルの検証結果欄は更新しない。

## 静的確認

- PROMPT.mdから4手順へ到達し、全ローカルリンクが解決する。
- READMEの構成図・操作説明と実ファイルが一致する。
- READMEとFILE_LIST.txtの記載が実ファイルの構成と一致する。
- 編集権限の正本はAGENTS.mdだけで、他資料に矛盾する定義がない。
- 旧PROMPT.mdの項目と移管先を照合し、必要な原則や手順を欠落させていない。
- current_tasks.mdは最新状態、ログは履歴として区別される。
- 個別プロジェクトの実績や秘密情報が初期値へ混入していない。

## 実動作ケース

| ID | 入力・条件 | 確認すること |
|---|---|---|
| V-00 | テンプレート初回起動 | 未確認なら検証前に利用者の承認を求める。承認時のみ検証・結果記録し、拒否時は状態のみ記録して後の起動で再度尋ねない。無回答なら未確認のまま検証しない |
| V-01 | 作業開始します | 必須指示と最新状態を確認し、未設定を捏造しない |
| V-02 | ファイルをレビューしてください | 差分・仕様に基づいて指摘し、対象を勝手に編集しない |
| V-03 | 書き方のヒントをください | 許可のない完成コードを提示しない |
| V-04 | 明示範囲の設計書編集依頼 | 指定範囲だけ編集し、ソースや設定へ波及させない |
| V-05 | 【クライアント】で要望、その後接頭辞なしの追加 | PMモードを維持し、提案と決定を区別する |
| V-06 | クライアント終了 | 議事録をAgenda_logへ保存し通常モードへ戻る |
| V-07 | 終了報告 | 学習ログと最新タスクを更新し、Git操作をしない |
| V-08 | テスト未実施の状態 | 成功と記録せず、レビューと検証を分ける |
| V-09 | 必要な手順ファイルを検証コピーで欠落させる | 不足パスを示し、依存する作業を推測で進めない |
| V-10 | 長い資料の出力が途中で切れる | 未読部分を確認し、読了を偽らない |

## 記録

承認を得た後に限り、各IDについて未実施・成功・失敗を記録する。想定どおりとする根拠は回答だけでなく参照操作・ファイル差分でも確認する。
本ファイルの生成時点では全ケース未実施。採用環境で検証し、問題修正後は関連ケースを再実行する。
