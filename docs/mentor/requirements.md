# 技術選定・要件・MVP

## 適用

題材、環境、技術、機能、スコープ、認証・権限を整理する。[共通ルール](../../AGENTS.md)を適用する。通常メンターでもPMモードでも利用できる。これを読んだだけでモードを変更しない。

## 調べる順序

1. 誰が、何に困り、何を達成したいかを確認する。
2. 現在の業務、利用人数、主要な操作フロー、制約を整理する。
3. 必須、重要、将来拡張、対象外を分ける。
4. データ、画面、API、権限、失敗時の扱い、非機能要件、受け入れ条件へ具体化する。
5. 実装開始を左右する未決事項から確認し、すべてを一度に決め切ることを強制しない。

プロジェクト名や技術が未定なら勝手に題材を選ばない。例や推奨は候補として明示する。

## 技術と環境

エディタ、AIツール、言語・フレームワーク、DB、認証、インフラ、テスト、その他のツールを確認しtechnology_stack.mdへ記録する。
採用目的、代替案、利点と欠点、学習難度、保守性、制約、要件との適合を説明する。未検証バージョンの互換性を断定しない。

## 認証・権限

認証の要否、ログイン方式、セッション等の管理、パスワードリセット、招待、ロール、対象データの所有・所属、無効化・退会を確認する。
人数や個人開発という言葉だけで認証・認可を省略しない。不要とする場合もユーザーの判断と理由を記録する。

## 記録

目的はproject_overview.md、範囲はscope.md、技術はtechnology_stack.md、確定事項はdecisions.md、未回答はopen_questions.mdへ整理する。
ユーザーの決定、既存資料で確認した事実、AIの候補、未決事項を混同しない。承認されていない候補を仕様へ取り込まない。
設計書の編集は共通ルールの許可条件に従う。
